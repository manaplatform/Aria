# Weather Intelligence

Conductor discovers weather and location operations through the shared registry. The configured primary chooses whether to use them. Requests execute in Electron main, through the conversation-scoped capability bridge, rather than in a renderer or browser tab. Weather does not require a project. Provider data is untrusted and cannot grant permissions.

MET Norway Locationforecast 2.0 supplies point forecasts; `weather.current` is an estimate from forecast data, not an observation. The free Open-Meteo geocoding endpoint supplies place-name candidates and GeoNames attribution. Its free service is restricted to non-commercial use. Forecasts are converted into the selected units and local calendar days; missing fields are null and partial days are identified. A weather presentation node can only use a completed weather receipt from the same execution.

Settings and cached responses are held locally in the desktop profile. Clearing the weather cache cancels outstanding weather requests and removes its stored entries. Requests disclose the user's IP address and requested place or coordinates to the providers. Weather calls are not available to background jobs, temporary chats, programs, or turns containing private runtime evidence. Device location is currently unavailable; specify a place or coordinates instead.

The runtime uses HTTPS, public-address resolution, TLS identity verification, provider host allowlists, bounded redirects and bodies, local request coalescing and rate limits, a timeout, and conditional requests. It truncates coordinates to four decimals and waits at least three hours before repeating a MET forecast request, or longer when HTTP freshness headers require it. A local hashed request ledger retains refresh limits after cache clearing, eviction, or restart. Clearing cached data can therefore leave a location temporarily unavailable until its refresh interval expires. Failed requests are conservatively subject to the same local interval. The runtime retries a transient DNS lookup once before network dispatch; it does not automatically retry provider HTTP requests or launch a browser. These local controls cannot enforce MET Norway's application-wide traffic ceiling across installations.

Before production distribution, a human with authority must read and accept the [MET Norway terms](https://docs.api.met.no/doc/TermsOfService.html), confirm the application's contact identity, verify that anticipated aggregate traffic stays within those terms, and monitor provider limits. The [Open-Meteo terms](https://open-meteo.com/en/terms) limit its free API to non-commercial use; a commercial release needs a separately licensed geocoding solution. Direct requests are permitted by MET Norway at moderate volumes, with the privacy and aggregate-traffic constraints described in its [FAQ](https://docs.api.met.no/doc/FAQ.html). No hosted proxy or centralized quota service is included.

The bundled coordinate-to-time-zone lookup uses `@photostructure/tz-lookup` under CC0-1.0. Retain the generated dependency inventory and notices in releases. Local deterministic tests do not establish live provider availability or verify platform location permissions.
