# Computer Use

Conductor discovers Computer Use in ordinary desktop chat. The primary explicitly selects an environment and protocol. Use **Settings → Web & Browser** to enable the Aria AI browser. Use **Settings → Tools** to verify OpenAI Computer Use or typed image results for the configured primary. The two probes send synthetic images and verify their continuation separately.

## Environments

- **Managed browser.** Open an authorized public page with Browser and attach its AI tab to Computer Use. Visual interaction quarantines the tab’s network. Use structured Browser tools for supported online form submission, or navigate the Computer Use session to a fresh, independently validated public page. Ordinary web research and Personal tabs retain their existing policies. Public downloads require an observed direct HTTPS link. The upload broker supports observed same-origin single-file multipart forms with an explicit file and destination approval. Forms with session credentials, other fields, or unsupported behavior remain user-controlled.
- **Public media playback.** The structured Browser tool can play a supported media element on a page opened from a supplied URL or Web Search result. AI tabs start muted. Aria reports playback after the media advances and Chromium detects audio. Stop playback from the chat header. Playback also stops when the conversation changes or the tab closes or navigates.
- **Private browser sign-in.** Private sign-in opens a new ephemeral session for one HTTPS origin. During takeover the user operates the view directly and the model receives no screenshots or page observations. Returning control suspends network activity and permits only structural metadata with opaque control references. Authenticated screenshots, automated authenticated input, and private downloads stay user-controlled. Sites that require a separate identity-provider origin need a Personal tab and user-reviewed sharing.
- **Virtual desktop.** Build the reviewed image locally, copy its immutable image ID into **Virtual desktop image ID**, and verify against the configured Docker endpoint. The desktop uses its own offline display and filesystem. Mousepad and Writer are the available applications. Stage conversation files by ID and publish supported outputs from `/workspace/outputs`. Code-assisted interaction runs separately through Part 2’s Shell sandbox and requires its pinned workspace image.
- **Local desktop.** In **Settings → Tools → Execution and knowledge**, choose **Select a full screen** on macOS 15.2 or later, or Windows 10 (build 19041) or later. Verify **Aria Computer Use image observations** for the primary. On macOS, allow Aria in **Screen & System Audio Recording** and the native helper in **Accessibility**. Use **Check permissions** after changing OS settings to reuse the saved selection.

**Allow access until revoked** is selected by default. The approved display can share screenshots with the named primary and receive mouse input from any active chat, including after Aria restarts. **Change display** replaces the selection with one approval. **Revoke** deletes it and stops active local desktop sessions. Switching primaries, disconnecting the display, or disabling OS permissions suspends the affected access. Returning to the same configuration restores eligibility. For one-time access, clear the checkbox, start the local session in the selected chat within two minutes, and approve each launch, mouse action, or screenshot transfer.

```sh
docker build -t aria-virtual-desktop apps/desktop/virtual-desktop
docker image inspect aria-virtual-desktop --format '{{.Id}}'
```

## Execution and data

Electron main owns each foreground lease. Switching conversations, taking control, and stopping input invalidate earlier observation references. Provider action batches pass the same checks and approval prompts as Aria calls. The API forwards authorized observations only to the current primary. Browser and virtual desktop action records distinguish submitted input from verified results. An interrupted attempt can be uncertain even when the provider finished generating its tool call.

Local mouse actions support movement, left/right/middle-click, double-click, left-button drag, and horizontal or vertical scrolling. Positions use screenshot pixels. Aria checks the current display identity, geometry, and the area around each target before input. The native helpers check OS permissions and keep each gesture within the selected display. A cursor move can be confirmed by the OS. Check a fresh screenshot for the visible effect of a click, drag, or scroll. The Windows driver uses standard desktop privileges, so secure desktops and apps that block injected mouse input remain user-controlled.

The SQLite runtime schema stores the ongoing grant separately from session ownership, approval decisions, and artifact provenance. Local sessions start with new observations after a restart, chat switch, or device reconnection. Frames are bounded and transient. Browser restore opens a fresh profile. Virtual desktop restore requires the same authorized container and matching isolation settings. Published downloads and outputs use the existing artifact store and retention policy.

## Verification

Run `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm licenses:check`, and `pnpm --filter @aria/desktop test:electron`. Keep provider protocol fixtures separate from live provider probes. On each shipping OS, run the native gesture smoke with `pnpm --filter @aria/desktop exec cross-env ARIA_TEST_LOCAL_MOUSE=1 pnpm test:electron --grep "native mouse gestures"` on an interactive desktop with the system permissions granted. Verify display selection, OS permission revocation, mixed monitor scaling, and teardown there as well. Verify the graphical image on the configured Docker host with real capture, input, save, and cleanup before advertising it. Keep disconnected or unsupported combinations unavailable. Real accounts, transactions, communications, and destructive operations stay outside automated fixtures.
